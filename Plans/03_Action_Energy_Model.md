# Action & Energy Model — параметрическая модель правил (design only)

> Статус: **зафиксированная идея, НЕ реализована.** Текущий код намеренно
> остаётся на дискретной legacy-модели (Plant/Herbivore/Carnivore). Этот
> документ — целевая god-sim модель и оценка стоимости перехода.
> Надстройка над [02_GodSim_Design_Review.md](02_GodSim_Design_Review.md)
> (решения #6 «правила как данные» и #8 «параметр → формула → последствие»).

## Идея в одну фразу

Виды — это не дискретные категории, а **трофический номер** на спектре. Энергия
течёт через **Action**, выход которого — **функция от номера(ов)**. И диета, и
фотосинтез — это один и тот же механизм с разной формулой.

## Трофический номер

Каждая сущность имеет `TrophicLevel` (напр. 0–100):

```
0 ───────── 20 ───────── 40 ───────── 60 ───────── 100
растение    переход    травоядное    переход     хищник
```

Дискретные виды текущего кода — частный случай: Plant ≈ низ, Herbivore ≈
середина, Carnivore ≈ верх.

## Action — правило над номером и полями среды

Эффект любого Action = функция от трофического номера(ов) и полей среды, и всё
настраивается владельцем мира. Action меняет не только энергию, но и положение.

### 1. Активный Action (сущность → сущность)

Поглощение одной сущности другой. Выход — **функция разницы** уровней
(`eater` E, `prey` P):

- **Ешь вниз** (E > P): база `X`, полезность убывает **−1% за единицу** разницы
  → ноль на разнице 100.
- **Ешь вверх** (E < P): база `X` на равном номере, убывает **−10% за единицу**
  вверх → ноль уже на разнице 10.
- **Равный номер**: максимум `X`.

```
usefulness
   X │      ╱╲
     │    ╱    ╲___
     │  ╱(−10%/u) ╲___ (−1%/u)
   0 │╱______________╲________________
     -10   0                       +100   (P − E)
       ешь вверх    ешь вниз
```

Асимметрия = окно хищничества: легко есть близких/нижних, тяжело — высших.

### 2. Пассивный Action (среда → сущность)

Сущность впитывает **энергополе среды** в своей точке.

- Поле имеет доступность (напр. `solar = 100%` здесь).
- Выход = `g(level) × availability`.
- **«Solar»**: `g` убывает с номером (0 → 10%/тик, выше → меньше). ←
  **обобщённый фотосинтез**.
- **«Oxygen»**: `g` плоская — все уровни впитывают одинаково.

> Это растворяет «фотосинтез категориален»: фотосинтез — не особый вид, а
> пассивный Action с убывающей по номеру кривой над полем `solar`.

### 3. Move (локомоция — сущность → положение)

Перемещение — тоже Action, параметризованное номером и средой:

- **Базовая скорость = `h(level)`**: ниже номер → медленнее (кривую задаёт
  владелец мира). Сейчас это разрозненный `MaxSpeed` от трейта скорости.
- **× density-фактор**: чем плотнее среда в точке (поле `density`), тем
  медленнее. Стоимость энергии за движение — тоже функция этих величин.

> Поля среды модулируют не только энергию: `solar`/`oxygen` → поглощение,
> `density` → скорость. Одно поле — разный эффект через свой Action.

### Action'ы влияют друг на друга (кросс-модификаторы)

Текущий Action сущности модулирует выход других. Пример:

- **Move ↓ пассивное поглощение** — энергия уходит в движение, впитывается меньше.
- **Idle ↑ пассивное поглощение** — покой: наоборот, впитывается/сохраняется больше.

Знак и величина модификатора — настройка владельца мира. Значит `Ruleset`
описывает не только выход каждого Action, но и **матрицу влияний Action → Action**.

## Единая картина

```
Среда: поля (solar, oxygen, density, …)   ← параметры мира (#8)
        │ пассивный Action: yield = g(level) × field      (энергия)
        │ move:             speed = h(level) × density     (положение)
        ▼
   Сущность (TrophicLevel 0–100, energy, position)
        ▲ активный Action: yield = f(level_eater − level_prey) × X
        │
   другая сущность
```

## Минимальный шов (когда будем реализовывать)

- `TrophicLevel` (0–100) у сущности (рядом с `Kind`).
- `IRuleset` с `ActiveYield(eaterLvl, preyLvl)`, `PassiveYield(lvl, field)`,
  `MoveSpeed(lvl, density)` и матрицей `ActionModifier(current → affected)`.
- Дефолт `ClassicRuleset` воспроизводит текущие числа (фотосинтез = пассивный
  solar, диета = активная, скорость = от трейта). Существующие тесты зелёные.

## Оценка стоимости перехода (почему сейчас можно остаться на legacy)

| Часть | Стоимость потом | Зависит от now/later? |
|-------|-----------------|------------------------|
| Диета: дискрет → номер+формула | 🟢 низкая (всё в `GameRules`) | нет, одинаково |
| Пассивные Action / энергополя | 🟡 net-new подсистема | нет, одинаково |
| Разрастание `switch(SpeciesKind)` | 🔴 растущий долг | **да** — растёт со временем |

**Вывод:** переход недорог, потому что правила уже централизованы в
`GameRules`. Единственный растущий долг — разброс `Kind`-проверок.

### Дисциплина, удерживающая стоимость низкой (соблюдать уже сейчас)

- Держать энергию/диету/бой/метаболизм **внутри `GameRules`** (одно место).
- **Не растаскивать** `switch (Kind)` / `Kind ==` по `Simulation`, поведениям,
  презентации. Если ветвление по виду неизбежно — заворачивать в метод
  `GameRules`, а не инлайнить.

При этой дисциплине будущая миграция = переписать тела методов `GameRules` +
добавить подсистему энергополей, а не переписывать движок.

## Открытые вопросы (на момент будущей реализации)

- Полная таксономия Action (помимо активного/пассивного — что ещё?).
- Точные формы кривых `f` и `g` (подбор баланса).
- Как `TrophicLevel` сосуществует с пользовательскими атрибутами сущности из
  god-sim DSL (#6): номер — это один из параметров или производное?
- Модель энергополей: статичные/диффундирующие/восполняемые поля в регионах.
