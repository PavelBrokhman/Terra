## 1. Идея

Виды — это не дискретные категории, а **трофический номер** на спектре. Энергия
течёт через **Action**, выход которого — **функция от номера(ов)** и **полей
среды**. И диета, и фотосинтез, и движение — это один и тот же механизм с разной
формулой, и всё настраивается владельцем мира.

---

## 2. Параметры сущности

### Трофический номер

Каждая сущность имеет `TrophicLevel` (напр. 0–100):

```
0 ───────── 20 ───────── 40 ───────── 60 ───────── 100
растение    переход    травоядное    переход     хищник
```

Дискретные виды текущего кода — частный случай: Plant ≈ низ, Herbivore ≈
середина, Carnivore ≈ верх.

### Два рода параметров

1. **Средо-зависимые (совместимость) — КОНСТАНТА.** Привязывают сущность к
   среде: trophic level, кислородная потребность, переносимость гравитации/
   плотности. Не развиваются. Сверяются с параметрами территории
   (см. [Совместимость](#совместимость-suitability)).
2. **Action-зависимые — РАЗВИВАЮТСЯ.** Растут от использования (эффективность
   поглощения, движение, …). См. [Развитие и баланс](#развитие-и-баланс).

### Развитие и баланс

У сущности — набор **развивающихся параметров** (эффективность поглощения,
качество движения, сила, …). Это «статы» с уровнями.

**Рост от использования.** Параметр развивается, когда выполняется **завязанное
на него действие**: много двигаешься → растёт движение; много впитываешь → растёт
поглощение. Practice → рост.

**Баланс: upkeep пропорционален уровню.** Каждый уровень параметра **тратит
энергию из среды в пассивном режиме** пропорционально величине. Высокий стат
дорог в содержании.

> Зачем: иначе ставишь параметр на 100 и получаешь **god-сущность**. Upkeep +
> конечность поля делают сильные статы самоограничивающимися — их нечем кормить,
> если на территории много таких же потребителей.

**Экологический контур:**

```
параметр ↑ → больше upkeep + больше потребление поля
        → поле истощается (регенерирует медленнее, чем тратится)
        → дефицит → конкуренция → ограничение роста/популяции
        → равновесие (carrying capacity)
```

Это feedback-loop'ы из 01/02 god-sim доков, выраженные через параметры +
конечные поля.

## 3. Среда

У среды свои параметры с градациями: `gravity`, `oxygen`, `density`, …
Средо-зависимый параметр сущности сверяется с одноимённым параметром территории.

### Энергополя

Источник энергии для [пассивных Action](#пассивный-action-среда--сущность).

- Поле имеет доступность (напр. `solar = 100%` здесь).
- Поле **конечно и регенерирует**: поглощение его истощает, со временем оно
  пополняется. Много потребителей на территории → дефицит и конкуренция за поле
  (естественная ёмкость среды).
- Поля модулируют **разное**: `solar`/`oxygen` → поглощение энергии,
  `density` → скорость движения.

### Совместимость (suitability)

Потребность сущности `N` против уровня территории `C` → пригодность `S ∈ [0,1]`.
Асимметрично (как формула еды); знак и крутизну задаёт владелец мира:

```
дефицит (C < N):  S = 1 − k_low  × (N − C) / N
избыток (C ≥ N):  S = 1 − k_high × (C − N) / N
S = clamp(S, 0, 1)
```

Пример `N=25`, `C=50` (избыток, (C−N)/N = 1.0):

| `k_high` | S | смысл |
|----------|-----|-------|
| 0   | 1.0 | избыток безвреден — чистое «need» |
| 0.5 | 0.5 | вдвое больше нормы → половинная пригодность |
| 1   | 0.0 | удвоение токсично — предел переносимости |

`S` управляет (выбор хоста): эффективность пассивного поглощения **×S**, либо
upkeep **×1/S**, либо гейт жизнеспособности (`S=0` → территория несовместима —
это и есть проверка совместимости при онбординге бога из `02`-дока).

## 4. Action

Эффект любого Action = функция от трофического номера(ов) и полей среды, и всё
настраивается владельцем мира. Action меняет не только энергию, но и положение.

### Активный Action (сущность → сущность)

Поглощение одной сущности другой. Выход — **функция разницы** уровней
(`eater` E, `prey` P):

- **Ешь вниз** (E > P): база `X`, полезность убывает **−1% за единицу** разницы
  → ноль на разнице 100.
- **Ешь вверх** (E < P): база `X` на равном номере, убывает **−10% за единицу**
  вверх → ноль уже на разнице 10.
- **Равный номер**: максимум `X`.

```
usefulness
   X │      ╱╲
     │    ╱    ╲___
     │  ╱(−10%/u) ╲___ (−1%/u)
   0 │╱______________╲________________
     -10   0                       +100   (P − E)
       ешь вверх    ешь вниз
```

Асимметрия = окно хищничества: легко есть близких/нижних, тяжело — высших.

### Пассивный Action (среда → сущность)

Сущность впитывает [энергополе](#энергополя) среды в своей точке.

- Выход = `g(level) × availability`.
- **«Solar»**: `g` убывает с номером (0 → 10%/тик, выше → меньше). ←
  **обобщённый фотосинтез**.
- **«Oxygen»**: `g` плоская — все уровни впитывают одинаково.

> Это растворяет «фотосинтез категориален»: фотосинтез — не особый вид, а
> пассивный Action с убывающей по номеру кривой над полем `solar`.

### Move (локомоция)

Перемещение — тоже Action, параметризованное номером и средой:

- **Базовая скорость = `h(level)`**: ниже номер → медленнее (кривую задаёт
  владелец мира). Сейчас это разрозненный `MaxSpeed` от трейта скорости.
- **× density-фактор**: чем плотнее среда в точке (поле `density`), тем
  медленнее. Стоимость энергии за движение — тоже функция этих величин.

### Кросс-модификаторы

Текущий Action сущности модулирует выход других:

- **Move ↓ пассивное поглощение** — энергия уходит в движение, впитывается меньше.
- **Idle ↑ пассивное поглощение** — покой: наоборот, впитывается/сохраняется больше.

Знак и величина модификатора — настройка владельца мира. Значит `Ruleset`
описывает не только выход каждого Action, но и **матрицу влияний Action → Action**.

## 5. Единая картина

```
Среда: поля (solar, oxygen, density, …)   ← параметры мира (#8)
        │ пассивный Action: yield = g(level) × field      (энергия)
        │ move:             speed = h(level) × density     (положение)
        ▼
   Сущность (TrophicLevel 0–100, energy, position)
        ▲ активный Action: yield = f(level_eater − level_prey) × X
        │
   другая сущность
```

## 6. Наследие

Глобальный параметр **игрока (бога)**, переживающий потерю территории/мира.
Две роли.

### XP-коэффициент

Front-loaded ускорение прокачки параметра на уровне `L`:

```
speedup(H, L) = H × 10% / 2^(L−1)
```

| Heritage | Ур.1 | Ур.2 | Ур.3 |
|----------|------|------|------|
| 1 | +10% | +5%  | +2.5% |
| 2 | +20% | +10% | +5%   |

**Рост наследия:** малая доля заработанного опыта уходит в наследие (пример:
наследие 0, уровень 0, +100 опыта → +1 в наследие ≈ 1%).

**Зачем:** выбили с территории → на другой сущности развиваются быстрее.
Сильный буст на старте + затухание ÷2 за уровень → ускоряет **восстановление**,
но не делает поздних сущностей имбой (per-world баланс остаётся целым).

### Индикатор уровня и матчмейкинг

Наследие отражает **общий уровень сущностей игрока** (среднеарифметическое
уровней). Владелец территории задаёт допустимую **уровневую полосу**, и при
входе бога его уровень сверяется с ней — часть проверки при онбординге (`02`),
рядом с [suitability](#совместимость-suitability). Защита: прокачанный игрок не
зайдёт на территорию новичков и не вынесет всех.

> Открытый вопрос: гейт — это само `Heritage` или средний уровень сущностей?
> Тесно связаны (оба растут из одного опыта), но это разные величины.

## 7. Реализация

### Минимальный шов

Когда будем реализовывать — минимальная точка входа, не ломающая Phase 2:

- `TrophicLevel` (0–100) у сущности (рядом с `Kind`).
- `IRuleset` с `ActiveYield(eaterLvl, preyLvl)`, `PassiveYield(lvl, field)`,
  `MoveSpeed(lvl, density)` и матрицей `ActionModifier(current → affected)`.
- Дефолт `ClassicRuleset` воспроизводит текущие числа (фотосинтез = пассивный
  solar, диета = активная, скорость = от трейта). Существующие тесты зелёные.

Развивающиеся параметры, конечные поля, upkeep, наследие — слои поверх шва.

### Стоимость перехода

Почему сейчас можно остаться на legacy:

| Часть | Стоимость потом | Зависит от now/later? |
|-------|-----------------|------------------------|
| Диета: дискрет → номер+формула | 🟢 низкая (всё в `GameRules`) | нет, одинаково |
| Пассивные Action / энергополя | 🟡 net-new подсистема | нет, одинаково |
| Разрастание `switch(SpeciesKind)` | 🔴 растущий долг | **да** — растёт со временем |

**Вывод:** переход недорог, потому что правила уже централизованы в
`GameRules`. Единственный растущий долг — разброс `Kind`-проверок.

### Дисциплина

Удерживает стоимость низкой — соблюдать уже сейчас:

- Держать энергию/диету/бой/метаболизм **внутри `GameRules`** (одно место).
- **Не растаскивать** `switch (Kind)` / `Kind ==` по `Simulation`, поведениям,
  презентации. Если ветвление по виду неизбежно — заворачивать в метод
  `GameRules`, а не инлайнить.

При этой дисциплине будущая миграция = переписать тела методов `GameRules` +
добавить подсистему энергополей, а не переписывать движок.

## 8. Открытые вопросы

- Точные формы кривых: `f`/`g` (выход), `h` (скорость), upkeep(уровень),
  скорость роста параметра от использования, темп регенерации полей.
- Полный список параметров сущности и какие действия их «прокачивают».
- Связь `TrophicLevel` с набором параметров: номер выводится из них или задаётся
  отдельно? (склоняемся к «сводка/производное»).
- Модель полей: гранулярность (на регион/ячейку), диффузия между соседями,
  баланс regen vs потребление.
- Полнота таксономии Action (active / passive / move / modifiers — что ещё?).
- Гейт матчмейкинга по наследию vs по среднему уровню сущностей.
