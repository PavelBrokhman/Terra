## 1. Общая архитектура

Игра основана на клиент-серверной модели. Сервер управляет симуляцией, а клиенты
подключаются к нему, чтобы взаимодействовать с игрой.

- **Сервер:**
  - Управляет картой и игровыми сущностями.
  - Обрабатывает логику поведения, заданную игроками.
  - Контролирует баланс, генерацию мира и параметры существ.
- **Клиенты:**
  - Могут подключаться к разным серверам.
  - Загружают свои модели, карты и логику поведения.
  - Управляют настройками своих существ.

## 2. Сущности игры

### 2.1. Основные объекты
1. Растения – источник пищи для травоядных.
2. Травоядные – питаются растениями, могут быть атакованы хищниками.
3. Хищники – охотятся на травоядных.

### 2.2. Параметры существ
Каждое существо имеет параметры, изменяющиеся в зависимости от условий. Все
параметры находятся в диапазоне 0–100:
- 0 – смерть.
- 1-30 – низкий уровень.
- 31-70 – средний уровень.
- 71-100 – высокий уровень.

Начальные значения параметров зависят от типа существа. Например:
- Хищники: высокая атака, средняя защита.
- Травоядные: высокая защита, средняя скорость.

## 3. Логика поведения

В игре нет встроенного ИИ – поведение существ задаётся пользователями через
программируемую логику.
- Игроки пишут код поведения для своих существ.
- Логика может быть реализована через микросервисы.
- Логика обрабатывает сигналы (например, "вижу врага", "мало еды") и выдаёт
  команды ("атаковать", "бежать").

Пример микросервиса:
- Сервер отправляет запрос "какое действие выполнить?"
- Микросервис обрабатывает данные и отвечает "идти вперёд" или "атаковать".

## 4. Опыт и еда
1. Опыт начисляется при активных действиях (атака, защита).
2. Опыт временный – закрепляется только после еды.
3. Модификатор усвоения влияет на эффективность поглощения еды.
4. Игрок сам распределяет опыт между параметрами и развитием.

## 5. Сетевая структура
- Использование REST API или gRPC для общения сервера с микросервисами.
- WebSockets для обмена данными в реальном времени.
- Возможность локального запуска сервера или подключения к удалённому серверу.

## 6. Гибкость настройки
Игроки могут:
- Загружать свои модели.
- Разрабатывать свои карты.
- Писать свою логику поведения.
- Настраивать параметры мира (баланс, скорость развития, сложность).

## 7. Варианты реализации тактового режима
Игра движется согласно тактам, длительность которых задаёт сервер. За один такт:
- Сервер отправляет актуальную информацию игрокам.
- Ожидает ответ в установленное время (например, 5 секунд, но может быть и 1 час
  или даже неделя).
- Если игрок не отвечает, его модели считаются проигравшими и становятся едой.

Возможные режимы тактов:
1. **Фиксированное время такта** – сервер ждёт строго определённое время и затем
   обрабатывает ход.
   - Хорошо для динамичных игр, но может быть неудобно для медленных стратегий.
2. **Гибкое время такта** – игра ждёт всех активных игроков, но не дольше
   установленного максимума.
   - Ход завершается досрочно, если все игроки ответили.
   - Подходит для пошаговых стратегий.
3. **Комбинированный вариант** – сервер может учитывать персональные лимиты.
   - Например, если 80% игроков ответили, такт завершается досрочно.
   - Если игрок пропустил несколько тактов подряд, его модели начинают исчезать.
4. **Режим автономии** – если игрок не отвечает, его модели переходят в
   автоматический режим (например, защищаются или ищут еду).

## 8. Возможные технологии
- Язык разработки: C# (Stride Engine + .NET Core).
- База данных: SQLite (локально), PostgreSQL (для онлайн-серверов).
- Сетевой стек: ASP.NET Core Web API / gRPC.
- Поддержка пользовательского кода:
  - Интерпретируемые скрипты (Lua, Python).
  - Компиляция пользовательских DLL.
  - Запуск через Docker-контейнеры.

## 9. Развитие проекта
1. **Первый этап:** Базовая симуляция (существуют сущности, параметры меняются,
   модели движутся).
2. **Второй этап:** Подключение микросервисов для логики.
3. **Третий этап:** Поддержка сетевой игры.
4. **Четвёртый этап:** Пользовательские карты, настройки и расширяемость.

Этот подход обеспечит гибкость, масштабируемость и удобство для
игроков-программистов.
